# Spec: the GPU port, every noise on wgpu in WGSL

**Status:** Accepted 2026-11-14 (the owner: "otherwise agreed and you can proceed", after Copilot's review was
answered), with the six decisions as recommended. Written from
[the GPU fast track](../../design/2026-11-01-gpu-fast-track.md) (Accepted 2026-11-01), its stage 2, and
[the spike](../../../Spikes/gpu_fast_track/README.md) that measured stage 1.
**Board:** [`2026-11-01-gpu-fast-track`](../../plan/board/2026-11-01-gpu-fast-track.md)

What gets built, exactly enough that the plan is a list of tasks and a reviewer can check the result against this page. The
design says why; this says what. Where the two disagree, the design's decisions hold and this page is the bug. The design's
four decisions are not reopened here: the GPU only when asked for; WGSL the source and naga the rest; everything HogNoise has
in the first release; the tolerance measured per feature over a stated coordinate range, then fixed. Its precision is
float32 throughout, with large coordinates left to the roadmap's large-coordinate stage.

## Facts this rests on

Read from the code at `3830011`, not assumed:

- **One parameter record.** Every kernel takes the same 27 scalars in one order, `NoiseParams.kernel_args()`
  (`params.py:430-474`). It derives `fractal_bounding`, the two 3D transforms, `noise_fractal_type` (NONE when the fractal
  is a domain warp) and `warp_fractal`, and passes the warp amplitude already multiplied by `fractal_bounding`. The seed is
  an unbounded Python `int`; the kernels wrap it to 32 bits first (`seed = _wrap32(seed)`). The shader takes this tuple,
  wrapped and packed, so the derivations stay in Python once.
- **The chain per point** (`scalar.sample_one_3d`, `scalar.py:1915-2005`; 2D at `sample_one_2d`, 1830): the domain warp on
  the raw coordinates (`warp3`, 1543) then the frequency multiply, or the frequency multiply alone; the gradient perturb
  (`perturb3`, 1622); the transform (`_transform3`, 1713); the fractal (`fractal3`, 1774) calling the single noise
  (`noise_single3`, 1683) per octave. `scalar.py` defines 73 functions; 67 are per-point logic a port needs. The other six
  are `_wrap32`, which WGSL's `i32` does natively, and the five batch drivers, which become the shader's entry points.
- **The features** (`params.py`): eight noise types (OpenSimplex2, OpenSimplex2S, Cellular, Perlin, ValueCubic, Value, and
  FastNoiseSIMD's white noise and classic Simplex), eight fractal types (None, FBm, Ridged, PingPong, the two domain-warp
  fractals, and FastNoiseSIMD's Billow and RigidMulti), five cellular distances, nine cellular returns (with NoiseLookup and
  Distance2Cave), three domain warps, the five perturbs (four gradient ones and Normalise), and the 3D rotations. Every noise
  exists in 2D and 3D; the FastNoiseSIMD features, 3D only at their source, are evaluated at z = 0 in 2D.
- **What the vectors cover.** The hog set has 95 features. Every one is sampled at frequency **0.01**. The scatter point sets
  reach 4,096 units and `grid_y0` 2,048, so the noise-space coordinate (`coordinate * frequency`) reaches about **41**.
  The 48 FastNoiseSIMD features have **no `scatter_2d` case** (their originals were 3D only), so their 2D path is compared by
  nothing. The two `genasgrid` grids cover only classic Simplex FBm, with scales (1, 1, 1) and (1, 0.5, 2): powers of two.
- **The arithmetic.** The hash is signed 32-bit multiply-and-xor with arithmetic shifts that are load-bearing
  (`scalar.py:487-489`, `1077`); WGSL's `i32` multiply wraps and its `>>` on `i32` is arithmetic, so both carry over. After the
  float32 frequency multiply the CPU computes in **float64** (`scalar.py:15-17`); WGSL has no float64. With a domain warp the
  CPU promotes the **raw** coordinates and warps them in float64 before the multiply (2061-2064). White noise reads the bit
  pattern of its float32 input (`_fns_bits`, 1074-1077) and scales the hash in float64 (1070), so it is bit-exact on the GPU
  only where its input is: no warp, no perturb, no rotation (`_transform3` runs in float64) and no fractal with a lacunarity
  that is not a power of two. Elsewhere one changed input bit changes the output anywhere in its range.
- **The discrete choices.** `_fast_floor` (170: `int(f) - 1` for every negative `f`, whole numbers included), `_fast_round`
  (179) and, in classic Simplex and the perturb, `np.floor` pick lattice cells; the simplex families branch on which region a
  point is in; cellular picks its nearest cell (`new_distance < distance0`, 974 and 1038). A float32 difference near one of
  these edges can flip the choice. In the gradient noises a flip is continuous (neighbouring regions agree on their shared
  edge), so it shows as drift. In cellular it is not: CellValue returns the nearest cell's hash and NoiseLookup samples at
  the nearest cell's point, so a flip jumps the output by up to its whole range, at the few points within float32 error of an
  edge. White noise jumps the same way, as above.
- **The tables.** Four float32 tables, `GRADIENTS_2D` (256), `GRADIENTS_3D` (256), `RAND_VECS_2D` (512) and `RAND_VECS_3D`
  (1024): 2,048 values, 8 KB (`tables.py`). The spike bound its table as a storage buffer (`noise2.wgsl:17`).
- **No recursion.** NoiseLookup samples one more noise, one level deep, never cellular (`params.py:368-369`), with no
  fractal; WGSL forbids recursion, and none is needed. Loops are octaves (no upper bound, `params.py:364, 370`), warp and
  perturb octaves, the cellular 3x3 and 3x3x3 searches, and Distance2Cave's second scan.
- **The ladder.** `backends.select` skips a negative-priority rung without probing it (rule 2), so an override-only rung's
  availability check runs only when it is asked for. A probe that returns false gives the reason "is_available() returned
  False"; one that raises gives its exception's message (`backends.py:107-118`). `fastnoiselite` is registered at -10
  (`samplers.py:370-378`).
- **The harness** (`conformance.py`) calls `fn(case.params, xs, ys, zs)` for every case (405-409), grids included: a point
  set's `from` is loaded and never used, so `sample_grid` is exercised only by `test_kernels.py:435-461`, outside the
  harness. A `points` rule has a bound (absolute, or scaled per point by `max(1, max |coordinate| * frequency)`), an optional
  `min_correlation` and an optional absolute `within: {scale, fraction}`. `check` takes one `bound` for the whole run and
  catches only `NotImplementedError` from a rendering (408). Of the 326 original cases, 43 have a bound: 16 noise and 27 warp.
  The other 275 are advisory and 8 shape.
- **The boundary.** `tests/test_package_boundary.py` has one global `ALLOWED` set (26) for its scan of every module, and runs
  a fresh interpreter that refuses `wgpu`, imports `hog_noise` and samples the default ladder. `python-project.md` says the
  package never imports a graphics stack.
- **CI** (`tests.yml`) runs four legs, installing the `dev` extra (numba, the binding, Pillow, pytest) or `test`; none has
  a GPU or `wgpu`. Every leg installs the member editable.

## The rung

`hog_noise.gpu`, one module, `src/hog_noise/gpu.py`. It registers the rung `wgpu` on the `noise` capability at priority
**-20**: override only, never chosen by the ladder, reachable as `make_sampler(params, backend="wgpu")` or
`HOG_NOISE_BACKEND_NOISE=wgpu`. `wgpu` is imported **inside** the module's functions, never at its top, so importing
`hog_noise` or using any other rung never loads it.

- **Availability.** `is_available` imports `wgpu` and gets the device; on failure it **raises** `RuntimeError` naming the
  cause ("wgpu is not installed: install hog-noise[gpu]", "no adapter: ..."), so the ladder's message carries it.
- **One device per process**, created on first use and kept, with its pipelines; `is_available` and every sampler reuse it,
  so building a hundred samplers costs one device. The adapter is wgpu's default, or the first whose name contains
  `HOG_NOISE_WGPU_ADAPTER`. The adapter's name and back end are logged at INFO once and exposed as `gpu.adapter_info()`.
- **`GpuSampler(params)`** has the calls every sampler has, with the same shapes and dtypes: `sample_points(xs, ys, zs, out)`,
  `sample_points_2d(xs, ys, out)`, `sample_grid(start, shape, scales)`, `warp_points(xs, ys, zs)`,
  `warp_points_2d(xs, ys)` and `sample(x, y, z=0.0)`. `sample` is `sample_points` on one point: correct, and slow on
  purpose.
- **The octave cap.** An `octaves` or `perturb_octaves` above **32** is refused when the sampler is built, with
  `NotImplementedError` naming the field: a shader loop runs as long as its uniform says, and a long one can stall the device
  until the driver resets it. `NotImplementedError` is what the harness reads as *unsupported*, so a run reports it rather
  than aborting. The CPU rungs keep no cap.
- **`sample_grid` computes its coordinates on the GPU** from the grid index, as the numba rung does: no coordinate
  buffers. Per axis the coordinate is `f32(start + index) * f32(scale)` in float32, where the CPU rounds the float64 product
  to float32 (`scalar.py:2313-2317`). The two agree when the scale is a power of two and `start + index` is below 2^24; for any
  other scale they can differ in the last bits, which the tolerance covers like any other drift.
- **The uniform** is `kernel_args()` with the seed wrapped to `i32`, packed as the shader's `Params` struct: integers `i32`,
  floats `f32`, padded to a multiple of 16 bytes. The CPU uses the float64 values of `lacunarity`, `gain`,
  `fractal_bounding` and the rest; their float32 rounding is part of what the tolerance measures.
- **The shader** is read with `importlib.resources.files("hog_noise") / "wgsl" / "noise.wgsl"`, so it loads the same from a
  wheel and from an editable install.

## The shader

One hand-written file, `src/hog_noise/wgsl/noise.wgsl`, shipped in the wheel (`uv_build` packs everything under
`src/hog_noise/`; the build's pull request lists the wheel's contents to show it). It is a port of `scalar.py`, function for
function, with the CPU function's name in a comment above each WGSL function, so a reader can hold the two side by side.

- **Entry points**, each `@compute @workgroup_size(64)`: `sample_points_3d`, `sample_points_2d`, `sample_grid`,
  `warp_points_3d`, `warp_points_2d`. Bindings: the `Params` uniform; the tables, one read-only storage buffer; the
  coordinate arrays (`array<f32>`, one per axis, read only); the output (`array<f32>`, read and write); for `sample_grid`, a
  second uniform with start, shape and scales.
- **Dispatch on the parameters at run time**, as `scalar.py` does: a `switch` on the noise type, the fractal, the cellular
  distance and return, the warp and the perturb. One shader serves every `NoiseParams`.
- **The tables** are a storage buffer, as the spike's were. Module-scope `const` arrays are the alternative; the plan
  measures both in the task that first builds the pipelines and keeps the storage buffer unless `const` is faster.
- **The hash** uses `i32` with wrapping multiply and arithmetic shift, matching `_hash2`/`_hash3` and the FastNoiseSIMD
  hash bit for bit. `_fast_floor`'s quirk is reproduced, not corrected.
- **Precision is float32 throughout.** No float64 emulation and no coordinate split.
- naga validates the file when the pipelines are built; a test builds every pipeline, so a shader that does not validate
  fails the suite on any adapter, software ones included.

## The tolerance

**One tolerance file per rendering**, `vectors/tolerance/wgpu.json`, beside the vectors and in the same spirit: data that any
language reads, versioned with the vectors. It applies to the **hog** set only, which covers every feature; `check` raises
`ValueError` when given a tolerance with `reference` other than `"hog"`. Through the hog set the GPU is tied to the
originals only where an original case has a bound (the 43 above): there, its distance from the original is at most the two
bounds added. The other original cases are advisory or shape, and stay what they are for every rendering.

```json
{
  "format": 1,
  "rendering": "wgpu",
  "range": {"frequency": [0.01], "noise_coordinate_max": 41.0},
  "measured": {"record": "reports/gpu/<commit>/", "adapters": ["NVIDIA GeForce RTX 5090 (Vulkan)", "Microsoft Basic Render Driver (D3D12)", "llvmpipe (Vulkan)"]},
  "rules": [
    {"feature": "fnl/simplex_fbm", "kind": "continuous", "bound": {"scale": 5e-6, "coordinate_scaled": true}},
    {"feature": "fns/cellular_natural_cellvalue", "kind": "discrete", "bound": {"scale": 2.0},
     "within": {"scale": 5e-6, "coordinate_scaled": true, "fraction": 0.998}, "min_correlation": 0.999}
  ]
}
```

- **One rule per feature and output.** A rule names its feature as `<library dir>/<feature>`, the middle of a case id, and
  an optional `output`, `"noise"` or `"warp"`. A rule with no `output` judges every case of that feature: noise and warp,
  every point set. A feature has either one rule with no `output`, or at most one `"noise"` rule and one `"warp"` rule;
  any two rules that cover the same case of a feature (two with no `output`, two with the same `output`, or one with
  and one without), or a rule naming no feature in the manifest, are a `ConformanceError` at load. A case no rule covers
  **fails** with the note "no tolerance rule", so a feature or an output added later cannot pass by default.
- **`range`** states what the numbers were measured over: the frequencies and the largest noise-space coordinate in the
  vectors. The tolerance makes no claim outside it.
- **Two kinds of rule**, named in `kind`:
  - **continuous**, for a feature whose output moves smoothly with its input: a coordinate-scaled `bound`, nothing else.
  - **discrete**, for a feature where a flipped choice jumps the output: cellular CellValue and NoiseLookup, white noise,
    and any other feature the measurement shows jumping. Its `bound` is the width of the feature's output range, so it
    fails only a value that is NaN, infinite or far off the noise's scale; `within`, coordinate-scaled, holds a stated
    `fraction` of the points to the tight bound a continuous feature would get; `min_correlation` holds the rest in shape.
    Nearly every point agrees as tightly as a continuous feature, and the rest are flips, few enough to count.
- **How a number is fixed.** `tools/measure_gpu.py` runs every hog case on each adapter it is given and writes a record
  under `vectors/reports/gpu/<commit>/`, JSON and Markdown only (no `.f32`, so `load`'s check for unlisted vector files
  is untouched): per case and adapter, the largest difference, the largest difference over its coordinate-scaled unit, and
  the 99th percentile of that normalised difference, the correlation as the harness computes it
  (`compare.compare_values(ours, reference).correlation`), and the fraction of points outside each candidate tight bound,
  where the candidates are every 1, 2 or 5 step from 1e-7 to 1e-2 inclusive. The rules are written from it:
  - a continuous `scale` is the worst normalised difference over every adapter, times **2**, rounded **up** to the next 1,
    2 or 5 step (the spike's 2.03e-6 gives 5e-6);
  - a discrete `within.scale` is the worst 99th percentile over every adapter, times **2**, rounded up the same way, so the
    flips (well under 1% of points) do not set it and the tight drift does; it is coordinate-scaled, like a continuous
    rule's. Its `fraction` is one minus **twice** the worst recorded fraction outside that candidate, rounded **down** to
    three decimal places, and its `min_correlation` the worst recorded correlation rounded down to three. A feature whose
    99th percentile is itself a flip (more than 1% of points flipped) cannot be written by this rule: it is a finding for
    the owner, not a number;
  - once written, a rule is never loosened to make a run pass (the design's decision 4). A rule that a new adapter fails is
    a finding: the run is recorded, and loosening it is the owner's decision, in the pull request that does it.
- **The warp outputs** are measured like the rest. Their drift should follow the raw coordinate, not the coordinate times
  frequency, because the CPU warps in float64 before the multiply; if the measurement says so, their rule's bound is
  absolute (`coordinate_scaled: false`), which a rule may be.
- **The GPU comparison table** the design asks for beside `portability.md` is `vectors/portability-gpu.md`, written by
  `tools/measure_gpu.py`: per feature and adapter, the worst normalised difference and, for a discrete feature, the
  fraction flipped.

## The vectors grow

The hog set is generated (`tools/gen_noise_vectors.py --set hog`), so it can cover what the originals do not, at no capture
cost. Two additions, each a hog-only case with no original behind it:

- **`scatter_2d` for every FastNoiseSIMD feature**: 48 cases, so the z = 0 path of white noise, classic Simplex, the
  perturbs, Natural, NoiseLookup, Distance2Cave, Billow and RigidMulti is compared.
- **A grid at a scale that is not a power of two**, `genasgrid_0.7_1.0_1.3` (start (-64, -64, 1), shape (128, 128, 1)), for
  classic Simplex FBm and for OpenSimplex2 FBm: two cases, so the float32 grid coordinate is measured where it can differ.

`gen_noise_vectors.py`'s rule that a hog case exists for every distinct original (parameters, point set, output) gains these
two lists. The CPU renderings pass them at `Bound(0)` like every hog case.

## The harness change

In `conformance.py`, the only change to existing code:

- `Tolerance` (frozen dataclass: `rendering`, `range`, `rules`) with `Tolerance.load(path)`, which reads and validates the
  file against the manifest's features. A malformed file or rule is a `ConformanceError` naming the part.
- `within` takes `coordinate_scaled` (default false), in the manifest and in a tolerance rule, scaled per point as `bound` is.
- `check(..., tolerance=None, grid=None)`:
  - `tolerance` judges every hog case by its feature's rule; with `bound` as well, or with `reference` not `"hog"`, `check`
    raises `ValueError`.
  - `grid(params, start, shape, scales)` returns the grid's values in the point set's `order`. When it is given, a case on a
    point set with `from` is sampled through it instead of `sample`, so `sample_grid` is checked inside the harness. The
    numpy and numba renderings pass `grid` too, which retires nothing: `test_kernels.py`'s own grid test stays.
- `CaseResult` gains `rule` (the feature's rule kind, or `"manifest"`), and `Report.table()` a *Rule* column, so a report
  says which bound a case met.
- The command line gains `--tolerance PATH`; `--rendering wgpu` works once the rung is registered. `renderings()` keeps
  its two-value return, because 13 callers unpack it (the package's and the root's tests, `gen_noise_vectors.py` and the
  command line); a new `grid_rendering(name)` returns the grid callable, and the command line passes it.

## The package boundary

- `tests/test_package_boundary.py`: the scan takes a per-module allowance, `MODULE_ALLOWED = {"gpu.py": {"wgpu"}}`, on top
  of `ALLOWED`; any other module importing `wgpu` fails. `wgpu` stays in `FORBIDDEN_AT_RUNTIME`, so the fresh interpreter
  that refuses it still imports `hog_noise` and samples the default ladder.
- Two tests are added. With `wgpu` refused, asking for the `wgpu` rung raises `BackendUnavailable` whose message names the
  cause, not an `ImportError` traceback. With `wgpu` installed (skipped with the reason where it is not), a fresh
  interpreter that refuses nothing imports `hog_noise`, samples the default ladder, and finds no `wgpu` in `sys.modules`.
- `python-project.md`, *The package boundary*: the graphics-stack sentence becomes "It never imports a graphics stack, except
  `wgpu` in `gpu.py`, behind the override-only `wgpu` rung (the GPU fast track)."
- The member's `pyproject.toml` gains a `gpu` extra, `wgpu` (the plan pins the version it builds on). `dev` does not include
  it: a developer without a GPU keeps a working `dev`.

## CI

- **The existing legs** skip the GPU tests, with the reason, because `wgpu` is not installed.
- **Two new legs** install `dev,gpu` and run the whole suite on a software adapter: Windows (`windows-latest`, Direct3D 12's
  WARP adapter) and Ubuntu (`ubuntu-latest` with Mesa's `llvmpipe` Vulkan driver, `mesa-vulkan-drivers`). They set
  `HOG_NOISE_REQUIRE_GPU=1`, under which a missing `wgpu` or adapter **fails** the GPU tests instead of skipping them, so a
  leg that stops finding its adapter cannot go green. The variable is documented in `Docs/standards/testing-project.md`.
- **A real adapter** is run by hand on the owner's machine before the pull request leaves draft:
  `tools/measure_gpu.py` and the conformance run, whose output names the adapter, pasted into the pull request.

## Acceptance

Each line is a test or a recorded run, named in the plan:

1. **Every feature, every entry point.** On each software-adapter leg the `wgpu` rung passes every hog case (noise and warp,
   every point set, the three grids through `sample_grid` by the `grid` path) against `vectors/tolerance/wgpu.json`, with
   `report.complete` true: nothing unsupported.
2. **On real hardware.** The same run on the owner's GPU passes, and its output, naming the adapter, is in the pull request.
3. **It can say no.** A shader with the seed off by one fails. A rule whose `scale` is set to 0.9 times its case's recorded
   worst fails. A feature with no rule fails with "no tolerance rule". A discrete rule whose `fraction` is set above its
   recorded fraction fails. A scaled `within`, on a point set whose allowances differ, fails a point whose error is above its own allowance but
   below the largest allowance in the set, so an allowance applied to the whole set instead of per point is caught.
   The `grid` path, given a sampler whose grid is transposed, fails. `octaves=33` reports *unsupported*, and the run
   continues.
4. **The boundary holds.** `import hog_noise` and the default ladder load no `wgpu`, with `wgpu` installed and with it
   refused; only `gpu.py` imports it; asking for the rung without `wgpu` raises `BackendUnavailable` naming the cause.
5. **The ladder is unchanged.** With `wgpu` installed and an adapter present, `make_sampler(params)` still chooses numba or
   numpy, and every CPU test passes unchanged: an install never changes the numbers.
6. **The numbers follow from the record.** `test_measure_gpu.py` recomputes every rule's number from
   `vectors/reports/gpu/<commit>/` by the rounding rules above and compares it with the file; a hand-edited number fails it.
7. **The new hog cases hold.** numpy and numba pass the 50 new cases at `Bound(0)` on every leg.
8. **The gate passes** (`tools/check.py`, full) on every leg.

## Not in this

The stretch, stage 3: `tools/emit_shaders.py`, the HLSL, GLSL, Metal and SPIR-V files, and their compilers in CI. The
large-coordinate stage, and any tolerance claim outside the measured `range`. 4D, the node graph, FastNoise2's nodes. A GPU
rung chosen automatically. Bit-for-bit agreement with the CPU. Speed: no performance claim is made, so none is measured; a
benchmark is its own row.

## Decisions for the owner

The design settled the four that shape the work and its precision. These are the spec's; the owner accepted each as
recommended, 2026-11-14:

| Decision | Accepted | Alternative |
| --- | --- | --- |
| Where the GPU's bounds live | A tolerance file per rendering, beside the vectors, one rule per feature | Per-rendering rules inside `manifest.json`; or patterns over case ids, which let one rule cover many features and so break "per feature" |
| How a flipped cell is judged | The discrete rule: a range bound, a scaled `within` with a fraction, a correlation | One loose bound for the whole feature, which hides drift everywhere else in it |
| The margin on a measured number | Twice the worst, rounded up to a 1-2-5 step | The worst exactly, which the next adapter fails |
| Growing the hog set | 48 FastNoiseSIMD `scatter_2d` cases and one non-power-of-two grid, generated | Leave the vectors as they are, and the 2D FastNoiseSIMD path and the grid's rounding go unchecked |
| CI | Two software-adapter legs (Windows WARP, Ubuntu llvmpipe), failing when the adapter is missing; `dev` without `gpu` | Skip on CI and rely on the owner's machine |
| The octave cap | 32 on the GPU rung only, reported as *unsupported* | No cap, and a run with a huge octave count can hang the device |

## Open risks

- **The software adapters in CI.** The design's fact comes from the source project's Windows runner; Ubuntu's llvmpipe on a
  hosted runner is not yet proven for this repository. The plan's first task is a CI leg that only creates a device and
  dispatches one pipeline; if a leg cannot find its adapter, the leg is dropped and the pull request says so, the owner's
  machine carries acceptance 2, and acceptance 1 is restated as "where an adapter exists".
- **The size of the shader.** 67 functions in one WGSL file, perhaps 3,000 lines. naga's validation and the pipelines' build
  time are measured in the first task that builds them; the device and pipelines are built once per process regardless.
- **The warp's drift.** The CPU warps raw coordinates in float64; at 4,096 units float32 resolves about 5e-4, and the
  original warp bound is 4e-3. The measurement decides; the rule records it.
- **One frequency.** The vectors sample only frequency 0.01, so the tolerance is measured only to a noise-space coordinate of
  about 41. The spike measured larger drift at 0.05 farther out. A wider claim needs more hog cases at other frequencies,
  which is a later row, not this spec.

## Terms introduced

- **Tolerance file**: one rendering's bounds against the vectors, `vectors/tolerance/<rendering>.json`: one rule per feature,
  *continuous* (a coordinate-scaled bound) or *discrete* (a range bound, most points within a tight one, and a correlation),
  written from a recorded measurement over a stated range and never loosened to make a run pass.
- **Hog-only case**: a hog case with no original behind it, generated to cover what the originals do not (a FastNoiseSIMD
  feature in 2D, a grid at a scale that is not a power of two).

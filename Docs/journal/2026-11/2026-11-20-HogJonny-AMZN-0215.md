### 0.11.0: a candidate first, then the tag, two ways
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Once [PR #34](https://github.com/HogJonny-AMZN/HogNoise/pull/34) merged, @HogJonny-AMZN paused for the template's
0.11.0: `--update`, `--upstream` on git, a harness hook that refuses an inline script (the template's ledger entry 48),
parallel suites and a uv floor. The template's session asked HogNoise to try the release before it was tagged, and
the trial found four things: the guide sent a trial to `main`, which still named 0.10.2, so step 3 refused the lock;
the serial suite went from about 2 minutes to about 10, all of it in the three new git test files (313 s, 98 s and
19 s), and under 3 in parallel; the hook could only be proved from a session in this repository; and `--update` itself
could not be tried until a tag existed. The template fixed the first three in its 0.11.0
([ai-first-template PR #247](https://github.com/HogJonny-AMZN/ai-first-template/pull/247)).

When the tag came (v0.11.0, `4e5d6ef`), the update was redone from it: four files had moved since the candidate (the
hook, its test, `testing.md`, `updating.md`). Then, for the template's host plan, the tag's own `--update` ran on a
fresh worktree of `main` at 0.10.2. It took 14 seconds and made the same tree byte for byte, the lock included, apart
from what no release can write: `pyproject.toml` and `uv.lock`, the project's own. Its three small findings (a seeded
file still listed as a step to do, the first release's route through a clone left unsaid, a commit made with no hooks
not saying so) go to the template's 0.11.x.

The machine, for the work-machine comparison the handoff asks for: Windows 11 Pro 10.0.26300, an i7-13700K with 24
logical processors, git 2.53.0.windows.2, uv 0.13.9. From 0.10.2 to 0.11.0.

### Parallel tests, and what they did to the portability table
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Parallel tests broke two things the local gate could not see. First, CI: `tests.yml` installs the library's extras
with pip, not the workspace's `dev` group, so `pytest-xdist` never arrived and every leg stopped on `-n`. The `test`
extra now brings it, and the template's guide now says so too
([ai-first-template PR #248](https://github.com/HogJonny-AMZN/ai-first-template/pull/248)).

Then Copilot's review on [PR #35](https://github.com/HogJonny-AMZN/HogNoise/pull/35) asked what happens to
`vectors/portability.md` when its tests are split across workers. Measured, the table went from 210 lines to 47, and
the test passed. Every gate run on this branch had done it, and each diff had been reverted as the usual date stamp
without being read. The first fix tried, keeping the module on one worker with xdist's `loadgroup`, does not group at
all on this pytest and xdist, not even in a five-line test. So the writer now checks that it measured every committed
row: split, it skips and says how to regenerate (`-n 0`, 13 seconds); in one process, a missing row fails. It is P-2's
class again by a new route, so it is ledger entry P-15.
→ [P-15](../../standards/failure-modes-project.md)

### 0.11.1, by HogNoise's own `--update`
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

0.11.1 (`59dc9a0`) is the first release HogNoise could take with its own copy of `--update`. From a worktree of `main`
at 0.11.0 it took 8 seconds and made one commit: eight managed files, the lock and `framework.toml`, with no seeds and
no overrides to judge. `make check` passed all nine stages and `--upstream` says the lock is current.

What it could not show is 0.11.1's own change to the report: the line naming the seeds a run wrote, and the note that
its commit ran no hooks. The tool that ran is the repository's copy, 0.11.0's, so those arrive with the next update,
as the guide already says of `init`'s executable bit. The guide's other new bullets for 0.11.0's step 5 were already
true here: the pip extra and the time bound were fixed in [PR #35](https://github.com/HogJonny-AMZN/HogNoise/pull/35),
and the one conftest only puts its folder on the path. That PR said there was no conftest; there is one, with no hook.

The test stage took 411 seconds with the CPU at 58% from other work: a loaded number, not a regression.
→ [the guide's *0.11.1*](../../standards/updating.md)

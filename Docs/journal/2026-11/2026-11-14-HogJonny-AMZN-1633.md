### The GPU port's spec
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Board:** [`2026-11-01-gpu-fast-track`](../../plan/board/2026-11-01-gpu-fast-track.md)

With the framework current, the work turned to what the repository is for: the first rendering of HogNoise that is not
Python. The spec turns the accepted design's stage 2 into what gets built: a `wgpu` rung that is never chosen unless asked
for, one WGSL file ported function for function from `scalar.py`, and a way to say how close is close enough.

That last part is where the thinking went. The spike showed smooth drift that one coordinate-scaled number holds, but
reading the kernels for the spec turned up a belief to correct: not every feature drifts smoothly. Cellular picks its
nearest cell, and a point within float32 error of a cell edge can pick the other one, which jumps CellValue and
NoiseLookup by up to the whole output range. One loose bound for those features would hide every other kind of error in
them, so the spec proposes two kinds of rule: continuous, one scaled bound; and discrete, nearly every point held as tightly
as a continuous feature and the rest counted as flips. The rules live in a tolerance file per rendering beside the vectors,
written from a committed measurement, with a stated margin, and never loosened to make a run pass. The domain warp is the
other surprise: the CPU warps the raw coordinates in float64 before the frequency multiply, so its float32 drift will follow
the world coordinate, not the noise coordinate, and the measurement decides its rule.

A review with fresh eyes, before the pull request, scored the first draft 5 on its facts and found the belief that hurt
most: that the vectors already cover every feature everywhere. They do not. Every hog case is at one frequency, 0.01, so the
measured range ends near a noise-space coordinate of 41; the 48 FastNoiseSIMD features have no 2D case, because their
source was 3D only; and the harness never drove `sample_grid` at all. So the spec now grows the hog set with 48 generated
cases that have no original behind them, gives the harness a grid path, states the range the tolerance holds over, and
makes a rule name one feature rather than a pattern that could quietly cover several.

Six decisions are left for @HogJonny-AMZN; the risks the plan meets first are whether CI's hosted runners find a software
adapter at all, and how long naga takes over a shader of about 3,000 lines.

### Copilot's four, and the spec accepted

**Said by:** @HogJonny-AMZN

@HogJonny-AMZN: "first assess the copilot review, otherwise agreed and you can proceed". Copilot found four things the
fresh-eyes review had not, and all four held when read against the code. The rule-per-feature sentence contradicted the
warp rule beside it, so a rule now names a feature and an optional output. The discrete rule's tight bound had no stated
way to be chosen, and a worst-case number would have been set by the flips it exists to count, so it now comes from the

callers; Copilot named one, and there are 13, so the grid callable is a function of its own. And one of the "it can say
no" checks could never fail, because a scaled allowance is never smaller than its scale; it now tests the thing worth
catching, an allowance applied to the whole set instead of per point. The spec is Accepted with its six decisions as
recommended, and the plan is next. Reading the manifest for the plan corrected two counts: the hog set has 114
features, not 95, and two of the 48 FastNoiseSIMD features are grids, so the new cases are 46 in 2D and 2 grids, 48 in all.

### The GPU port's plan
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Board:** [`2026-11-01-gpu-fast-track`](../../plan/board/2026-11-01-gpu-fast-track.md)

With the spec merged, the plan turns it into eighteen tasks a builder can follow without having been here. It is ordered
by what could sink the work: the first task is nothing but a device and one pipeline on CI's hosted runners, because if
neither WARP nor llvmpipe appears there, acceptance 1 changes shape before any shader is written. Then the harness learns
what the GPU needs (a scaled `within`, a grid path, the tolerance file), the vectors grow by their 48 hog-only cases, and
only then does the shader come, one family at a time, each behind a gate that reports an unported feature as
*unsupported* rather than wrong, so the suite is green at every commit.

Reading the code for it settled two things the spec had left open. WGSL forbids a cycle in the call graph even where a
branch never runs, and NoiseLookup looked like one; it is not, because the CPU's lookup helpers call each noise directly
and never the dispatcher. And the rules must be re-derivable by a test, so which features count as discrete is a fixed
list, and a feature the list misses that still jumps stops the derivation as a finding for @HogJonny-AMZN rather than
quietly becoming a loose number. On this machine wgpu also lists WARP by name beside the RTX 5090, so two of the three
adapters can be measured here, and CI supplies llvmpipe.

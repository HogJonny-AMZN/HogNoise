### The north star, and the binding made boring
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Said by:** @HogJonny-AMZN

@HogJonny-AMZN: "a roadmap 'all the way' to the north star ... FastNoise2 parity, 4D, GPU and equivalent shader versions (HLSL,
WGSL, etc.), byte-identical, loose on the gpu front", and "this needs to be a all-in-one silo, the best most modern version of
a fastnoise for all use cases cpu and gpu". It is a Proposed design now, with gate G2 to lock it. FastNoise2's own headers were
read for the parity target rather than written from memory: about 50 node types, 2D to 4D, and any input fed by another node.

**Belief that changed:** the owner thought the source project had "kind of got there" on the GPU. It had proved the path, a
WGSL value noise read back against numpy at about 1e-6 relative, but no real algorithm ever ran on the GPU. The roadmap starts
from what was measured, not from the impression.

@HogJonny-AMZN: "we need to make it easy." The FastNoiseLite binding stopped being a rung users land on
([ADR-2026-11-01](../../decisions/ADR-2026-11-01-the-binding-is-reference-only.md)): installing numba now changes the speed,
never the numbers. The README's line breaks were the original complaint, not its wording: it is one line per paragraph now,
which renders the same in every previewer.
→ [the roadmap](../../design/2026-11-01-north-star-roadmap.md)

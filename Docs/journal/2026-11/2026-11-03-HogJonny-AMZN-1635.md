### The spike's bound, measured per point
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Copilot on [PR #8](https://github.com/HogJonny-AMZN/HogNoise/pull/8) was right twice: the points were drawn by Euclidean
radius while the bands claimed the larger coordinate, and yesterday's "within the bound in every cell" compared each band's
maximum with the bound at the band's top, which a point near its bottom could break unseen. Rerun on both back ends with
the points drawn by `max(|x|, |y|)` and every point divided by its own bound: none of 1,179,648 is over
`3e-6 * max(1, |coordinate * frequency|)`, the worst 2.03e-6. The claim stands, now as measured; the far band's largest
difference is 8.5e-3, not 7e-3.

### The harness design keeps everything the vectors hold
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Copilot on [PR #9](https://github.com/HogJonny-AMZN/HogNoise/pull/9) found three things the design would have dropped with
the `.npz` files: the two `genasgrid` grids sit on their own coordinates, not the shared y = 0 grid; nine warp cases carry
warped coordinates, which a noise-only `sample` cannot check; and eight originals are compared by shape and the FastNoiseLite
comparisons are advisory, so a pointwise pass for every original would be wrong. The design now gives each case a named point
set, an output (noise or warp, with an optional `warp` entry point) and a comparison (points, shape or advisory, with only the
first two deciding `report.ok`), and adds a test that every array in every `.npz` has a home before any is removed.
→ [the design](../../design/2026-11-02-conformance-harness.md)

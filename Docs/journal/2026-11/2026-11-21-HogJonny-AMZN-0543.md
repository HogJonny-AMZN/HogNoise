### Six GPU adapters: the 5090's D3D12 and OpenGL join the records
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Once [the account](../../design/2026-11-20-gpu-fast-track-account.md) merged, @HogJonny-AMZN said "proceed", and the
first item in its order was taken. Six measurement records were made at `efb910a`. Four were local: the 5090 on
Vulkan, D3D12 and OpenGL, chosen with `WGPU_BACKEND_TYPE`, and WARP. Two came from CI's run of the same commit: WARP
and llvmpipe. The tolerance file was derived from all six. 123 of the 125 rules are unchanged. `cubic_none`, in both
libraries, moved from 2e-7 to 5e-7: the 5090 drifts 1.19e-7 there on D3D12 and OpenGL, one float32 step at 1.0,
against at most 9.18e-8 elsewhere. Doubled to 2.38e-7, the next 1-2-5 step is 5e-7. Both back ends already passed the
old bound, so this follows from the rule and was not needed to pass. Loosening a rule is the owner's decision, so the
pull request asks for it.

The chain was run end to end first (P-12): the new file judges all 368 cases as passing on every local adapter. The
measurement tests read the record folder from the tolerance file now, instead of naming `0d419e9`, which would have
pointed them at the old folder. The README says how to choose a back end, and that the two variables do not combine.

The full gate's test stage failed once, on `test_warm_start_from_cache_is_fast`. Under `-n auto`, the subprocess that
primes numba's cache exited 1, and the test threw away its stderr. Alone, it passed in 1.5 s. Nothing under
`packages/` changed, so this is a flake, not this change. It is an Icebox row, because the next one will be just as
blind.

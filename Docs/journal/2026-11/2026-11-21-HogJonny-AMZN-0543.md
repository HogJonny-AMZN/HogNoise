### Six GPU adapters: the 5090's D3D12 and OpenGL join the records
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

Once [the account](../../design/2026-11-20-gpu-fast-track-account.md) merged, @HogJonny-AMZN said "proceed", and the
first item in its order was taken. Six measurement records were made at `efb910a`. Four were local: the 5090 on
Vulkan, D3D12 and OpenGL, chosen with `WGPU_BACKEND_TYPE`, and WARP. Two came from CI's run of the same commit: WARP
and llvmpipe. The tolerance file was derived from all six. 123 of the 125 rules are unchanged. `cubic_none`, in both
libraries, moved from 2e-7 to 5e-7: the 5090 drifts 1.19e-7 there on D3D12 and OpenGL, one float32 step at 1.0,
against at most 9.18e-8 elsewhere. Doubled to 2.38e-7, the next 1-2-5 step is 5e-7. Both back ends already passed the
old bound, so this follows from the rule and was not needed to pass. Loosening a rule is the owner's decision, so the
pull request asks for it.

The chain was run end to end first (P-12): the new file judges all 368 cases as passing on every local adapter. The
measurement tests read the record folder from the tolerance file now, instead of naming `0d419e9`, which would have
pointed them at the old folder. The README says how to choose a back end, and that the two variables do not combine.

The full gate's test stage failed once, on `test_warm_start_from_cache_is_fast`. Under `-n auto`, the subprocess that
primes numba's cache exited 1, and the test threw away its stderr. Alone, it passed in 1.5 s. Nothing under
`packages/` changed, so this is a flake, not this change. It is an Icebox row, because the next one will be just as
blind.

### The far-coordinate probe: the noise holds, the warps do not, and the bounds have a tail
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)

After [PR #40](https://github.com/HogJonny-AMZN/HogNoise/pull/40) merged, @HogJonny-AMZN said "proceed" again, and
the probe was next. It covers every hog feature's parameters, noise and warp, 2D and 3D: 246 probes, each with 65,536
fresh points in four bands out to 1,048,576 units. numpy rendered the reference, the GPU was judged by the feature's
own rule, and the probe ran on three adapters (the 5090 on Vulkan and D3D12, and WARP).

The first run counted 143 features, not 116: warp case ids have an extra part, and the probe now uses the conformance
module's own parser. A control was then added: on its case's own points, each probe must reproduce the hog set bit for
bit and pass. All 242 that have scatter points did, on every adapter.

Two beliefs did not survive. The account expected the discrete features to break first far out. Instead, the noise
rules hold to a million units, discrete ones included, and only the warp outputs fail. Their rules are absolute, while
their drift is 3 to 8 float32 steps of the coordinate. The second belief was that the bounds held anywhere in the
measured range. On fresh points in that range, 1 to 10 points in a million exceed them, at most 8.5 times, because the
bounds were fit to 4,096 points per case; on D3D12 that includes three NoiseLookup probes, a discrete rule. A check of
the write-up against all three result files caught two claims taken from the Vulkan run alone, and both were fixed
before the commit. The README now says so. Two changes to the derivation are on the Icebox for
the owner, and the large-coordinate row now holds only the CPU's own question.

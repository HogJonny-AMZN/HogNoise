### The harness, built
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Said by:** @HogJonny-AMZN

@HogJonny-AMZN accepted the plan ("accepted") and it was built task by task, test first. `hog_noise.conformance` loads
`vectors/` (raw float32, one manifest, every file digested and every path kept inside the folder) and checks any
rendering by points, shape or advisory. The conversion wrote 326 original cases and 320 hog cases, and its check matched
every array and coordinate of the 117 `.npz` files before they were removed, and failed when one value was nudged.

Measured, not assumed: FastNoiseLite's `grid_warp_3d`, never compared before, is at most 7.47e-4 off the oracle, so it is
now gated at the warp field's 4e-3; a full-environment run rewrites `portability.md` with one changed line, its date; the
gallery regenerates byte for byte; the vectors are 27 MB raw against 12 MB of `.npz`; and `test_kernels.py` takes 12 s
instead of 3 s, the harness running every case on numpy and numba.

Two things the plan had wrong, fixed in the build: the gallery read the `.npz` files, so it moved before they were removed
(Task 12 before 11); and moving `portability.md` broke two links the docs check enforces, so they moved with it. And one
belief changed: `tools/gen_noise_vectors.py` now imports `hog_noise`, whose floor is 3.11, so a FastNoiseSIMD capture
needs the source build ADR-007 records, not the 3.9 wheel the old docstring named.

Whether the hog set holds bit for bit across numpy 1.26, the latest numpy and Windows is the spec's open risk; CI on the
pull request measures it.

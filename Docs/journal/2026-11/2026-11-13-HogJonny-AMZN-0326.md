### The review that arrived after the merge
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Said by:** @HogJonny-AMZN

[PR #16](https://github.com/HogJonny-AMZN/HogNoise/pull/16) merged while its independent review was running, and Copilot
had not reviewed it. The review scored it 5/10 at its lowest, on error handling, and one finding was real damage waiting:
`generate_hog` deleted the hog folder before writing anything, so a kernel that failed part way left a folder neither
`load` nor a rerun could read. @HogJonny-AMZN agreed to fix every finding but one in a follow-up: the hog set is now staged
and swapped in whole (and regenerates byte for byte); a malformed manifest or parameter record is a typed error naming the
part; `from_dict` reads numbers as written; the command line exits 2 on a bad rendering or folder; captures are returned,
not collected in module state; a rejected verdict is tested. Declined: `Docs/PYTHON_UPGRADE_AND_FASTNOISE.md` keeps the
old vector path, as the spec says the planning record does. The cause is the order of the steps, so it is ledger P-8:
the deliberate review runs before the pull request opens.
→ [the ledger](../../standards/failure-modes-project.md)

The follow-up was reviewed before it left draft (P-8 applied to itself), and the review found the follow-up's own fix
incomplete: swapping the new hog set in began with `shutil.rmtree(..., ignore_errors=True)`, so on Windows a held handle made
the delete fail silently and the move then nested `hog/hog/`, and `generate_hog` reported success over a folder that would
not load. The swap is now renames only, with the old set put back on any failure and an atomic manifest write; a test
fails each of its three steps. Also fixed: the malformed shapes that still escaped `load` (`params` not an object, a
non-string id, a rule missing `bound` or with a non-numeric field), three tests that could not fail as written, the
`--rendering` message, and the spec, amended where the interfaces changed.

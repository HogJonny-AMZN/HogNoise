### The shader ships in three more languages
**By:** @HogJonny-AMZN · **Agent:** Claude Code (claude-opus-5-5)
**Board:** [`2026-11-01-gpu-fast-track`](../../plan/board/2026-11-01-gpu-fast-track.md)

With the move merged ([PR #33](https://github.com/HogJonny-AMZN/HogNoise/pull/33)) and ai-first-template 0.11.0 not yet
tagged, the emitter went ahead in [PR #34](https://github.com/HogJonny-AMZN/HogNoise/pull/34). naga-cli 29.0.2 wrote
what the plan measured, to the byte count: HLSL 133,502 bytes, SPIR-V 113,180, five GLSL files of 118,460 to 119,214.
Every compiler took every file the first time: FXC and DXC ten entry-point compiles on this machine and on
`windows-latest` (DXC 1.8 here, 1.9 there), glslang 16.2.0 five, spirv-val one. The finding worth carrying is that naga is
deterministic across systems: CI's regeneration job, building naga on Ubuntu, wrote the same nine files as the run on
Windows, so one committed set serves both.

Two of the instruments needed proving rather than trusting. A one-digit change in a WGSL comment failed the drift test
at once; the first change to `tables.py`, in a float's fifteenth digit, failed nothing, because float32 cannot hold it,
so a dead mutation passed for a moment as a blind test until a visible one failed as it should. And a hand edit to
`noise.hlsl` committed with its own hash passed all six test legs and failed only the regeneration job, which is why that
job runs on every push. Along the way the local uv 0.11.2 failed to build the wheel from its own sdist where uv 0.13.8
did not: one more reason for the uv floor the template takes in 0.11.0.
